# Магазин одежды - серверное приложение (REST API)

Лабораторная работа №1. Серверное приложение на C++ с REST API, базой данных PostgreSQL,
слоем работы с БД (модели + репозитории), миграциями, валидацией и тестами.

## Предметная область

Магазин одежды. Сущности:

| Таблица       | Что хранит                                   | Связи                                      |
|---------------|----------------------------------------------|--------------------------------------------|
| `categories`  | категории одежды (футболки, куртки ...)      | 1 категория - много товаров                |
| `products`    | товары: размер, цвет, цена, остаток на складе | товар принадлежит категории                |
| `customers`   | покупатели                                   | 1 покупатель - много заказов               |
| `orders`      | заказы со статусом и суммой                  | заказ принадлежит покупателю               |
| `order_items` | позиции заказа (товар + количество + цена)   | связывает заказы и товары (многие ко многим) |

## Бизнес-правила

1. Нельзя заказать товара больше, чем есть на складе. При создании заказа остаток уменьшается.
2. Статус заказа меняется только по цепочке `new -> paid -> shipped -> delivered`;
   отменить (`cancelled`) можно только из `new` и `paid`. При отмене товары возвращаются на склад.
3. Товар, который есть хотя бы в одном заказе, удалить нельзя.
4. Удалить можно только отменённый заказ.

## Технологии

- C++20, Visual Studio 2022, CMake
- PostgreSQL 16 (или новее)
- libpqxx - клиент PostgreSQL для C++
- cpp-httplib - HTTP-сервер
- nlohmann/json - работа с JSON
- GoogleTest - тесты
- vcpkg - установка библиотек

## Установка и запуск (Windows)

1. Установить Visual Studio 2022 с компонентом «Разработка классических приложений на C++»
   (в нём есть CMake), PostgreSQL и DBeaver.
2. Установить vcpkg:
   ```
   cd C:\
   git clone https://github.com/microsoft/vcpkg.git
   C:\vcpkg\bootstrap-vcpkg.bat
   setx VCPKG_ROOT C:\vcpkg
   ```
   После `setx` закрыть и снова открыть Visual Studio.
3. В DBeaver создать две пустые базы данных: `clothing_shop` и `clothing_shop_test`.
4. Проверить настройки подключения в файле `.env` (пользователь и пароль PostgreSQL).
5. Открыть папку проекта в Visual Studio: **Файл -> Открыть -> Папка**.
   Visual Studio сама запустит CMake и vcpkg (первый раз скачивание и сборка библиотек
   занимает 15-30 минут).
6. Выбрать запускаемый элемент `shop_api.exe` и нажать запуск.
   При старте автоматически применятся миграции, в консоли появится
   `Server is running on http://localhost:8080`.

Путь к папке проекта не должен содержать русских букв и пробелов (например `C:\dev\clothing_shop`).

## Тесты

- `unit_tests` - проверка отдельных функций (валидация, правила статусов, подсчёт суммы), БД не нужна.
- `integration_tests` - работа с настоящей БД `clothing_shop_test` (сервис + SQL + миграции + HTTP).

Запуск: в Visual Studio меню **Тест -> Обозреватель тестов -> Запустить все**
или запустить `unit_tests.exe` и `integration_tests.exe`.
Перед интеграционными тестами должна существовать пустая база `clothing_shop_test`.

## API

| Метод  | Адрес                    | Описание                                  | Успех |
|--------|--------------------------|-------------------------------------------|-------|
| GET    | `/categories`            | список категорий                          | 200   |
| POST   | `/categories`            | создать категорию                         | 201   |
| GET    | `/products`              | список товаров (`?category_id=1` - фильтр) | 200   |
| GET    | `/products/{id}`         | один товар                                | 200   |
| POST   | `/products`              | создать товар                             | 201   |
| PATCH  | `/products/{id}`         | изменить поля товара                      | 200   |
| DELETE | `/products/{id}`         | удалить товар                             | 204   |
| GET    | `/customers`             | список покупателей                        | 200   |
| POST   | `/customers`             | создать покупателя                        | 201   |
| PATCH  | `/customers/{id}`        | изменить покупателя                       | 200   |
| GET    | `/orders`                | список заказов с позициями                | 200   |
| GET    | `/orders/{id}`           | один заказ                                | 200   |
| POST   | `/orders`                | создать заказ                             | 201   |
| PATCH  | `/orders/{id}/status`    | сменить статус заказа                     | 200   |
| DELETE | `/orders/{id}`           | удалить заказ                             | 204   |

Итого 15 маршрутов: 6 GET, 4 POST, 3 PATCH, 2 DELETE.

Ошибки возвращаются в виде `{"error": "текст"}` с кодами: 400 - неверные данные,
404 - не найдено, 409 - нарушено бизнес-правило или дубликат, 500 - внутренняя ошибка.

### Примеры тел запросов

Создать товар (`POST /products`):
```json
{"name": "White T-shirt", "size": "M", "color": "white", "price": 1500, "stock": 10, "category_id": 1}
```

Создать заказ (`POST /orders`):
```json
{"customer_id": 1, "items": [{"product_id": 1, "quantity": 2}]}
```

Сменить статус (`PATCH /orders/1/status`):
```json
{"status": "paid"}
```

## Структура проекта

```
migrations/      SQL-файлы миграций (001-004), единственный способ менять структуру БД
src/
  main.cpp       точка входа: конфиг, миграции, запуск сервера
  config.*       чтение .env
  migrations.*   применение миграций
  models.h       структуры Category, Product, Customer, Order, OrderItem
  rules.*        валидация и чистые бизнес-правила (без БД)
  repository.*   весь SQL, преобразование строк таблиц в структуры
  service.*      бизнес-логика, транзакции
  routes.*       HTTP-маршруты
  errors.h       класс ошибки API
  query.h        обёртка для SQL-запросов с параметрами
tests/
  unit_tests.cpp
  integration_tests.cpp
.env             настройки подключения
vcpkg.json       список библиотек
CMakeLists.txt   правила сборки
```

Поток запроса: `routes` (HTTP, JSON) -> `service` (проверки, правила, транзакция) ->
`repository` (SQL) -> PostgreSQL.
